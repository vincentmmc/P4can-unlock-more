# 逆向来源与方法

这一页记录「141 项功能」到底是**怎么来的**，以及哪些是实锤、哪些只是推测。
写这个是因为设计图上不少帧号看起来很具体，实际上在固件里根本不存在 ——
不标清楚，后面接手的人（包括三个月后的自己）一定会照着错的帧号去实现。

## 1. 三路来源

### 1.1 TSL 安卓 App —— 位域与命令表（证据 A）

```text
TSL-Android.apk
  └── assets/SaaA_embed            （微信小程序容器包 __APP__.wxapkg）
        └── app-service.main.js     （业务逻辑，未混淆到不可读）
```

关键发现：

- `SETTINGS` 是一张字段表，每个字段带 `byte offset / shift / mask`，**直接给出**，
  不需要猜。44 个字段全部提取到 `data/feifan-menu-data.json` 的 `fields_full`。
- 所有写操作最终汇到一个 `writeConfigBytes()`：改完字节数组，整块用
  `CMD 163 (0xA3)` 发出去。没有「一个功能一条帧」这回事。
- 车身动作走 `CMD 167 (0xA7)`，payload 只有 1 字节动作码。
- 滚轮/首页快捷走 `CMD 187 (0xBB)`，payload 1 字节值。
- 帧头固定 `55 7F`，校验是 `(CMD + LEN_H + LEN_L + Σpayload) & 0xFF`。

### 1.2 Albert P4 固件里的看板（证据 A）

```text
Albert-P4-P1.6.4-V3.2-*-OTA.bin
  └── 偏移 284860 处的 gzip 流
        └── 718 KB HTML 看板
```

用 gzip 魔数 `1F 8B 08` 全盘扫描，逐个尝试解压，取解压后大于 100 KB 的第一个流。
得到的是另一个团队做的同类看板，功能命名比设计图准确得多：
「自动换挡」「远光提醒灯光」「常亮氛围灯」「迎宾灯效」「座椅记忆」这些
词条和真实 DOM id 都在里面，用来对齐命名、补全遗漏项。

### 1.3 P4CAN FUSION 设计图（证据 B）

两张界面设计图，给了分组结构、图标和一批功能名。**帧号不可信**，见第 4 节。

## 2. 证据分级

| 等级 | 含义 | 数量 |
|---|---|---:|
| `A` | 位域/命令直接读自反编译代码，或与固件源码逐行对上 | 94 |
| `B` | 只有设计图或命名推断，未在任一固件中命中对应帧 | 35 |
| `C` | 纯前端行为（仪表读数、备份导出、语言切换） | 12 |

页面上每条都挂了等级，不是装饰 —— `B` 级项在真机验证前不要当结论用。

## 3. 位域怎么读

```text
value = (byte[offset] >>> shift) & mask
```

写的时候三步：

```c
cfg[offset] &= ~(mask << shift);          // 1. 清位
cfg[offset] |= (value & mask) << shift;   // 2. 置值
send_frame(0xA3, cfg, len);               // 3. 整块回写
```

必须整块回写：设备端只接受完整的 35+ 字节配置块，单独发一个字段会被丢弃。

## 4. 纠错记录：设计图上不存在的四个帧号

设计图标了 `0x249`（脉冲远光）、`0x10C`（脉冲喇叭）、`0x3E2 / 0x3E3`（刹车灯爆闪）。
在 **Albert 固件**和 **P4 源码**里全文搜索这四个 ID：**命中 0 次**。

真相是这四项本来就走配置位域：

| 设计图写的 | 实际实现 | 位域 |
|---|---|---|
| 脉冲远光 `0x249` | `pluseHighBeam` | `byte25 >>> 0 & 3` |
| 脉冲喇叭 `0x10C` | `pluseHorn` | `byte27 >>> 6 & 3` |
| 刹车灯爆闪 `0x3E2/0x3E3` | `dynamicBrakeLight` | `byte33 >>> 6 & 3` |

`0x249` 在车上确实存在，但它是 **SCCM 拨杆状态帧，只读**。拿它当写入目标，
轻则无效，重则让灯光模块判定为持续拨杆、直接切近光 —— 设计图画的那个
「0x3E9 DAS 决策位」的思路方向是对的（走 DAS 才能真闪远光），
但 `0x3E9` 在固件里也不存在，Albert 的远光走 `0x3C2 Mux1`。

结论：这 27 项全部按位域重写，帧号只作为脚注留在 `implementation` 字段里。

## 5. 去重

三路来源有大量重叠，合并规则：

| 合并前 | 合并后 | 理由 |
|---|---|---|
| 滚轮挂挡（设计图「0x229」） | 并入 `自动换挡` | 同一个功能的两种输入方式 |
| 开启自动变道（`a2c`） | 并入 `打灯变道` | 0x293 注入就是它 |
| 氛围灯 / 迎宾灯光 | 并入 `常亮氛围灯` / `迎宾灯效` | 命名不同，位域同一个 |
| 电池预热 | 只留在「一键快捷」条 | 两处都放会刷两次 |
| 座椅/记忆、空调烘干 | 归到 `舒适与座椅` | 原来散在灯光组 |

去重逻辑写在 `tools/more/build_more.py` 顶部的 docstring 里，可复查。

## 6. 中英切换为什么这么绕

看板的中文机制是 `var DICT={}` 精确串匹配，而且**整个包在 IIFE 里**：

```js
(function(){ ... var DICT = {...}; function setLang(l){...} ... })()
```

外部拿不到 `DICT`、`cur`、`setLang`。绕法：

- 判断当前语言不能读 `cur`，改读 `localStorage.p4canLang`
- 静态文案走 `data-t-zh` / `data-t-en` 双份串
- 动态拼接的（`'Uploading ' + p + '%'`）用 `MutationObserver` 事后改写

还有一个坑：`DICT` 是 `setdefault(en, zh)` 建的，**先插入者胜**。
`'2 次'→'2 flashes'` 和 `'闪 2 次'→'2 flashes'` 会互相覆盖，
导致「闪 2 次」被翻回「2 次」。解决方式是删掉裸的 `'2 次'`，
次数类标签全部带上下文（`闪 N 次` / `N 声` / `N 次换挡`）。

## 7. 没搞清的

- `/api/feifan/*` 五个端点的**服务端**实现：契约已定，`web_api.h` 里没写
- `0xB0` 仪表帧的完整字段布局只解出一部分（门盖、电压电流温度 SOC 够用了）
- `0xAB` 256 字节配置块里，后半段有几个字节含义不明，未纳入页面
- 设计图上「Flipper 算法」的具体参数（周期、抖动）无法从材料反推，
  页面里只映射到 P4 现有的 nag 配置

以上都标在 `docs/FEATURES.md` 的对应条目里，不装懂。
